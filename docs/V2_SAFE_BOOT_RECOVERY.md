# Panda PWR V2 M1: safe-boot and recovery acceptance contract

**Status (2026-11-21): proposed test contract for [issue #17](https://github.com/danielbrownjr/DragonPWR/issues/17).** This is not evidence that any unexecuted test passed, not authorization to flash or energize a device, and not a production safety certification. V1 behavior and V1 hardware assignments are separate.

## Scope and evidence pedigree

This document defines **what must be established** before enabling V2 output drivers or relying on any recovery operation. It draws on:

- [V2 roadmap](V2_ROADMAP.md) and [M1 C3 build/USB-only acceptance](V2_M1_BUILD.md), including the operator-reported 2026-11-18 installation of inactive-output firmware `ec16bf5`; later C3 UI/browser/UART evidence is recorded in merged [PR #37](https://github.com/danielbrownjr/DragonPWR/pull/37) and [#38](https://github.com/danielbrownjr/DragonPWR/issues/38).
- Original private `engineering-report.md` and `factory-reverse-engineering.md`, read for this contract on 2026-11-21. These record earlier ROM/full-flash readback and **static** stock-firmware analysis. The private factory binary, NVS, credentials, MAC, serials and raw captures must stay out of the public repository.
- Current `main` source: [board contract](../components/dp_board/include/dp_board.h), [V2 inactive relay](../components/dp_relay/dp_relay_v2_inactive.c), [V2 inactive button](../components/dp_button/dp_button_v2_inactive.c), [app startup](../main/app_main.c), [V2 partition map](../partitions_v2.csv), and [C3 build defaults](../sdkconfig.v2.defaults).

**Evidence levels:** `S` = static source/image inference, `B` = native compile/link/host verification, `U` = operator-reported USB-only physical runtime, `P` = instrumented physical pad/rail/contact measurement, `E` = separately approved energized-output qualification, `R` = executed destructive restore/OTA rollback exercise. No level substitutes for a later level. Cite device variant, exact firmware SHA and artifact, board revision, instrument setup, stimulus, timestamps, outcomes and unresolved unknowns in each future test record.

> **Experimental exception (issue #18):** The opt-in, C3-only GPIO7 laboratory build in [V2_EXPERIMENTAL_SWITCHING.md](V2_EXPERIMENTAL_SWITCHING.md) deliberately commands GPIO7 only during explicitly acknowledged, bounded human-monitored tests. Its behavior is **not** qualified under the default inactive-output contract or safe for unattended use. This exception does not alter V1 or normal C3 builds and is not electrical qualification.

## Known V2 behavior and unresolved hazards

| Item | Source-supported observation | Not established / acceptance consequence |
|---|---|---|
| MCU/flash | C3 AZ rev 1.1, 40 MHz, 4 MiB; stock ROM response and image analysis; V2 uses app0 at `0x10000`, app1 at `0x200000` | Native images and USB-only boot do not establish electrical safety or successful return to stock |
| Stock AC path | **S:** GPIO7 high means desired ON at MCU/application level. Stock init stores desired AC = ON; GPIO18 falling-edge handler later applies queued GPIO7 state. Initial code does not directly drive GPIO7 high | GPIO18 physical source, edge availability/timing, external inversion, reset-pad behavior and actual relay contact state **unknown**. Do not assume AC is off before the edge or that an interrupt is a zero-cross signal |
| Stock USB | **S:** GPIO0 USB-A and GPIO1 USB-C are driven high during stock init (MCU-commanded ON); GPIO6 is driven low | Rail/port voltage, enable polarity at load, transient state during configuration and power domains **not measured**. Distinguish switched USB-C outlet from side USB-C programming |
| Other signals | **S:** GPIO6 auxiliary-output role unknown; GPIO10 meter-side input; SET among candidate GPIO5/8/9/19, some boot-strap pins. **ESP32-C3 GPIO18 and GPIO19 are internal USB Serial/JTAG D−/D+ pins**, respectively. ESP-IDF v5.3.5 defaults the secondary console to USB Serial/JTAG when supported, and `sdkconfig.v2.defaults` does not override it | The C3 inactive relay/button modules do not configure these pins, but that **does not leave GPIO18/19 electrically untouched**: USB PHY muxing and its D+ pull-up may affect the stock AC-edge and SET-candidate nets. This is source/config inference, **not measured pad state**; verify the generated candidate `sdkconfig` and physical net effects. Never inherit V1 GPIO6 input, GPIO10 button/SET or V1 GPIO7 active-low assumptions |
| DragonPWR C3 M1 | **Source/B/U:** C3 build selects `dp_relay_v2_inactive.c` and `dp_button_v2_inactive.c`; output writes return `ESP_ERR_NOT_SUPPORTED`, restore writes are rejected, and **these two modules do not configure output or input GPIOs**; USB-only app startup observed | An inactive driver does **not** prove physically de-energized AC/USB, especially before `app_main`, across resets, or with a failed semiconductor/relay. Placeholder state `false` is not contact feedback |
| Startup/OTA/NVS | `app_main` initializes NVS before inactive relay/button, then calls `dc_wifi_start()`, `dp_portal_start()`, and `confirm_running_image()`. A pending OTA image is confirmed after **both start calls return OK**, without requiring a client to reach the portal. C3 rollback is enabled in defaults. **S:** `init_nvs()` automatically calls `nvs_flash_erase()` for `ESP_ERR_NVS_NO_FREE_PAGES` or `ESP_ERR_NVS_NEW_VERSION_FOUND`; other persistent NVS failures reach `ESP_ERROR_CHECK` and can trigger a reset loop | Starting a portal is not proof of RF/HTTP reachability or electrical safety. **A corrupt/incompatible NVS scenario can irreversibly erase stored credentials/settings in firmware without a separate operator erase action.** Backup and restoration of NVS must precede any fault injection; rollback and resets still need independent verification |
| Recovery | **U:** original full 4 MiB stock backup digest was checked against device before reflashing; WCH ROM connection supported read and later DragonPWR app boot | Original unit **no longer runs stock firmware**. Writing back the backup, preserving NVS and verifying the full device, and running original stock afterwards remain **R NOT TESTED**. A full backup is not a tested restore |


**ESP-IDF source basis for the GPIO18/19 qualification:** [C3 IO_MUX definitions](https://github.com/espressif/esp-idf/blob/v5.3.5/components/soc/esp32c3/include/soc/io_mux_reg.h) assign the internal USB PHY D−/D+ to GPIO18/19; [ESP console Kconfig](https://github.com/espressif/esp-idf/blob/v5.3.5/components/esp_system/Kconfig) defaults the supported secondary console to USB Serial/JTAG, and the [USB Serial/JTAG guide](https://github.com/espressif/esp-idf/blob/v5.3.5/docs/en/api-guides/usb-serial-jtag-console.rst) describes the PHY D+ pull-up. Check the **generated** `sdkconfig` and the particular board's wiring before asserting the PHY's actual active pad state. No V2 electrical observation was performed for this change.

### Non-negotiable invariants

1. **Fail closed while unqualified.** On C3 V2, no **product output/input-control path** may configure or intentionally drive unqualified AC/USB/SET candidate GPIOs, accept an ON/LAST restore policy, claim switch control, or present placeholder OFF as measured output. **This does not establish that pins are electrically untouched by ROM, bootloader, the USB Serial/JTAG PHY or other platform subsystems**; GPIO18/19 are specifically implicated. Confirm actual candidate configuration and pad behavior before electrical claims.
2. **Boot safety starts before software.** Pin bias, strapping, driver inversion, external relay/USB supply behavior, and the reset-to-app gap must be measured and independently controlled before considering active drivers. V1's active-low GPIO7 preload algorithm is **not portable** to V2.
3. **No unseen resume.** Until separately specified and qualified, active-output V2 startup and post-fault recovery must not silently apply stored ON/LAST/queued commands. Exact restore policy and any timing/holdoff remain **design decisions**, not validated constants.
4. **No network dependence for physical safety.** Wi-Fi/portal/printer state is not a safety precondition; fail-safe behavior must remain defensible with no network, malformed NVS, or an unavailable meter/edge input.
5. **Maintenance requires its own boundary.** UI disablement and software authorization do not establish disconnected contacts. Reset, OTA, boot-slot selection, factory reset and return to stock require verified actual output state and operator-controlled safeguards.
6. **Independent protections.** Firmware commands cannot substitute for electrical isolation, appropriately rated current protection, interlocks, a safe instrumented fixture, and competent mains procedures. No energized test is authorized by this document.

## Test gates and acceptance matrix

**All items below are PROPOSED / NOT RUN under issue #17 unless evidence is specifically referenced.** For every scenario, retain an exact-candidate UART boot trace, reset reason when available, selected slot/OTA state, HTTP capability and output-state fields, and independent pad/rail/contact readings when that gate is authorized. Define allowable transient voltage/duration and instrument/sample-bandwidth criteria **before** testing, based on actual PCB/circuit and load ratings; this contract deliberately invents no numeric electrical pass threshold.

| ID | Condition / stimulus | Acceptance / expected outcome | Evidence level and prerequisite |
|---|---|---|---|
| SB-01 | Cold power application from fully discharged board, network unavailable | No actuation commanded by the inactive C3 driver; startup identifies C3/firmware/slot; instrumented evidence must later show whether any AC/USB or GPIO transient occurs **before** app init | **B/U source evidence partly exists; P NOT RUN.** USB-only without IEC/loads first; passive measurements only after board pads/ground identified |
| SB-02 | Warm software restart and serial-port open/reset | Same device identity with a **new boot ID after actual reset**; relay/button drivers remain inactive, no stored restore applied, output-control capabilities unavailable; no claim of physical off from API | **U partially observed** for non-reset serial opening; authorized controlled reset plus UART/network capture still needed |
| SB-03 | Watchdog/panic/reset loop | No privileged output state change from startup, reboot loop or NVS error; distinguish NVS-driven automatic erase/reset from other crash and OTA outcomes, and distinguish persistent from runtime logs | **S:** an NVS failure outside the two auto-erase cases propagates through `ESP_ERROR_CHECK` and may reset repeatedly. **NOT RUN:** inducing reset loops requires explicit approval, verified NVS backup and a bounded recovery plan; physical effects require P gate |
| SB-04 | Brownout, slow ramp, short power loss, abrupt disconnect/reconnect | Determine physical contact/rail/pad states before/during/after MCU supply loss and return, including output-driver fallback; no uncommanded energization under an approved design | **P/E NOT RUN.** Never simulate with live mains or loads absent a separately approved isolated, protected fixture and measurable abort plan |
| SB-05 | GPIO18 absent, stuck, bouncing, or mistimed edge | An eventual active driver must not falsely infer contact state or apply unsafe queued AC changes; characterize physical edge function first **and account for C3 USB Serial/JTAG D− on GPIO18**, unlike the stock GPIO18 input configuration | **S only; P/E NOT RUN.** First inspect generated `sdkconfig`, USB PHY mux/boot state, PCB routing and pad behavior; never inject/simulate edges into an unidentified net. Disabling/reassigning secondary console is a separate future design decision |
| SB-06 | GPIO6, SET candidates, strapping during startup | No unknown pin may command AC/USB; confirm GPIO10 meter-side use, SET wiring and **USB Serial/JTAG D+ pull-up/PHY behavior on GPIO19 (a SET candidate)** before enabling button input | **S/B inactive-driver basis; P NOT RUN.** Identify PCB nets, strapping and secondary-console configuration before probing or connecting test equipment; PHY activity is not GPIO inactivity |
| SB-07 | Blank/corrupt/incompatible NVS and restore values | Inactive C3 does not accept persisted ON/LAST or falsely report measured output; **firmware automatically erases the whole NVS partition** for `NO_FREE_PAGES`/`NEW_VERSION_FOUND` during `init_nvs()`, and other init failures can abort/reset. Record credential loss, reset reasons and outcome distinctly | **S source-confirmed; B partial; runtime/R NOT RUN.** Treat the test as **inherently destructive even without an explicit erase command**. First create and independently verify a secure partition-level NVS backup, document restoration and recovery path, then obtain separate explicit approval for fault injection. Abort if backup or test containment is uncertain |
| SB-08 | HTTP, legacy, product-control and local-input attempts to change outputs | All C3 output mutations rejected, no success response or UI actuator; no GPIO touches; audit alternate/provisioning paths and failure replies | **B + earlier host tests, U read-only UI; live mutation NOT RUN.** Do not issue output commands without separate approval even when expected to fail |
| SB-09 | Maintenance reboot, OTA upload, boot inactive slot, failed/interrupted update | Unsafe/unknown states prevent an unguarded maintenance action; track slot, `PENDING_VERIFY`/`VALID`/`INVALID`, reboots and recovery independently. **The current application confirms a pending image when `dc_wifi_start()` and `dp_portal_start()` return OK**, even if no client can reach it; this is not full recovery proof | **B startup flow; R NOT RUN.** Reboot requires approval; OTA/rollback/erase/write require distinct approval and known recovery path |
| SB-10 | Known good image vs. rollback, erased second slot, corrupted/incompatible slot | Tested recovery to a known bootable image or explicit safe failure, without treating stock otadata `VALID` as a successful rollback test | **S/U partition knowledge; R NOT RUN.** Preserve backup and obtain explicit destructive-test authority |
| SB-11 | Factory stock restore from private complete backup | Confirm exact target identity/flash layout, unmodified private 4 MiB source image and recorded source SHA-256. Any separately approved procedure must **restore the stock bootloader as part of the complete raw image at offset zero**, preserve the image's flash mode/frequency/size headers (explicit `keep` settings rather than accidental override), avoid erase-all unless separately justified, and verify the **entire restored flash** by full-range readback with a host-computed SHA-256 equal to the private recorded backup SHA-256 (or a documented equivalent full-range digest comparison supported by the selected tool) before treating restoration as completed. Assess stock startup's commanded ON defaults before energized use | **Backup U verified; restore R NOT RUN.** The WCH DTR/RTS ROM/stub entry and time parked in downloader are separate **unqualified pad-state windows**. Stock restore can bring back original NVS/credentials and stock ON commands; no unapproved erase, write, or test boot |
| SB-12 | Radio/provisioning unavailable; stalled HTTP polling | No physical safety reliance on browser identity, a network poll or stale UI state. C3 switching still unavailable | **U read-only acceptance partially observed; P NOT RUN.** Browser recovery evidence is not relay qualification |

**Gate precedence:** source review and native inactive-driver tests (S/B) → approved USB-only observation (U) → unpowered net identification and non-actuating passive electrical characterization (P) → independently approved controlled energized qualification (E) → separately approved destructive NVS/OTA/stock recovery drills (R). Some tests require more than one level. Do not skip electrical characterization because a USB-only web dashboard is healthy.

## Evidence collection template (one record per test and exact candidate)

| Field | Required record |
|---|---|
| Scenario | SB-ID, disposition `PASS` / `FAIL` / `BLOCKED` / `NOT RUN` |
| Device | V1 C2 or V2 C3, PCB revision, hardware/fixture ID stored privately |
| Candidate | Git SHA, app version, bootloader, partition table/slot, binary digest, ESP-IDF version |
| Scope/authority | Who explicitly approved which USB-only observation, reset, destructive write or energized test; limits and abort conditions |
| Setup | Actual power domains, IEC/load isolation, adapter wiring and independent protections; instrument model, bandwidth and calibration |
| Stimulus | Ordered steps, timing, network and NVS state; no secret values |
| Observations | UTC UART and HTTP timestamps, reset reason, boot/OTA state, heap/resource state; **independent** GPIO, USB rail, relay-contact/outlet voltage as required |
| Interpretation | Separate commanded, MCU-pad, measured-output and inferred state; mark absent evidence `NOT RUN`, not `PASS` |
| Recovery | Observed post-test state, known-good boot, backed-up data integrity and whether restore/rollback actually occurred |

## Explicit stop/abort conditions

- Missing/ambiguous PCB net/pad identity, unknown supply/ground reference, unexplained boot-strap interaction, uncertain isolation, unexpected output energization or unexplained electrical transient.
- Any observed GPIO/contact discrepancy, input edge with unknown origin, reset loop, boot-image mismatch, readback/digest failure, **unexpected NVS auto-erase (which may already have destroyed credentials before observation)**, or inability to verify the recovery path. Prepare backup/containment *before* a destructive stimulus; a stop condition cannot undo automatic erasure.
- Failure to capture the required evidence, unexpected drift of firmware SHA, or inability to keep the authorized test within its stated electrical/hardware scope.

Record the observation and **stop** the affected test; do not compensate with UI flags or speculative pin drive. Changing the code to actuate outputs belongs to separately authorized M2 work ([#18](https://github.com/danielbrownjr/DragonPWR/issues/18)). Future full qualification belongs to M7 ([#26](https://github.com/danielbrownjr/DragonPWR/issues/26)); issue #17 can be complete as a **reviewed contract** while physical tests remain explicitly open.
